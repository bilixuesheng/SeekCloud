所有提交的作者都用用户本人：`XUESHENG <162862376+bilixuesheng@users.noreply.github.com>`，签名在 GitHub 上要显示 Verified。新机器上没有原来的签名密钥，开工前：

1. 生成一把新的签名密钥：

   ```sh
   ssh-keygen -t ed25519 -C "162862376+bilixuesheng@users.noreply.github.com" -N "" -f "$HOME/.ssh/seekcloud_signing"
   ```

2. 把公钥（`$HOME/.ssh/seekcloud_signing.pub` 的内容，可以公开）发给用户，请用户在 https://github.com/settings/ssh/new 加成 Signing Key（Key type 选 Signing Key）。用户确认加好之前不推送。
3. 在仓库里设本地 git 配置。云端机器的全局 git 配置会把作者设成 Claude，并用环境自带的签名程序，所以必须用 `--local` 覆盖：

   ```sh
   git config --local user.name "XUESHENG"
   git config --local user.email "162862376+bilixuesheng@users.noreply.github.com"
   git config --local gpg.format ssh
   git config --local user.signingkey "$HOME/.ssh/seekcloud_signing"
   git config --local gpg.ssh.program ssh-keygen
   git config --local commit.gpgsign true
   ```

4. 每次提交后在本地验签，要看到 `Good "git" signature`，作者和提交者都是 XUESHENG：

   ```sh
   printf '%s %s\n' "162862376+bilixuesheng@users.noreply.github.com" "$(cat "$HOME/.ssh/seekcloud_signing.pub")" > "$HOME/.ssh/allowed_signers"
   git -c gpg.ssh.allowedSignersFile="$HOME/.ssh/allowed_signers" log --show-signature -1
   ```

5. 每次推送后查 GitHub，`verified` 要是 `true`：

   ```sh
   curl -s https://api.github.com/repos/bilixuesheng/SeekCloud/commits/<sha> | jq .commit.verification
   ```

## 已定的决定

### 范围

- C 组的工单重开在本仓库，B 组（计费和多账户）不搬。
- 和新功能重叠的旧工单不单独搬：#59 按"开放插件市场"重写，#38 的部署和备份并进图形化部署、告警走多渠道通知，#49 并进多渠道通知，#65 并进一键更新。

- 首次设置管理员密码不做防抢先（用户：抢先的人也没有 key）。

### Agent（dsh）

- dsh 修改版放在一个单独的公开仓库，作为本仓库的 git 子模块。
- 插件照 dsh 默认：Agent 可以自己装插件，只装在本会话的沙箱里；SDK 的插件管理工具保持打开。
- dsh 的四种 Agent 模式（标准、PTC、极简、创造）、轨迹视图、插件市场"发现"页只在 dsh 网页版有，SDK 用不了。SeekCloud 在自己的界面里重做：模式放进模型弹层，轨迹视图作为会话页的另一种显示，插件市场作为设置里的一页。dsh 里没有叫"代码模式"的，最接近的是 PTC 模式。
- 默认思考强度是高档，设置里可以改默认值，每个会话也能单独选。
- 不做 DeepSeek 账号登录。dsh 的账号登录是浏览器 OAuth（PKCE），回调只支持本机或 SSH 端口转发，不支持远程反向代理；SeekCloud 在远程服务器上，做不到同样的体验（得让用户手动复制回调地址，也可能违反 DeepSeek 的条款）。

### 模型网关、提供方和用量

- DeepSeek API key 在部署向导和设置里填，加密存放。
- 每个会话只记用量（输入、输出、缓存命中的 token 数），不换算成钱。
- 多提供方照 dsh：设置里可以添加多个提供方，每个有接口地址、key 和模型；选模型时列出所有提供方的模型，管理员手动选。出错只在同一提供方内重试，同一会话连续 3 次失败就暂停回合，并提示可以换模型。不做自动切换和熔断。
- 会话中途换模型 = 重启 dsh 进程再 `session/resume`。dsh SDK 的模型路由是整个进程固定的。
- 余额用 DeepSeek 官方接口 `GET https://api.deepseek.com/user/balance`（API key 认证，已核实：返回 `is_available`，以及按币种的 `total_balance`、`granted_balance`、`topped_up_balance`），只对 DeepSeek 官方提供方显示。dsh 只有登录 DeepSeek 账号才显示余额，这是 SeekCloud 自己加的。

### 沙箱和宿主机

- 并发只按宿主机的资源（内存、磁盘）调度，不设数字上限；资源不够就排队。
- Windows 上的沙箱宿主机两种都支持：
  - WSL2 + 自装 Docker Engine + Sysbox：Sysbox 官方没列 WSL2，但维护者实测可用；不能用 Docker Desktop 的引擎，不能开 mirrored 网络；
  - Hyper-V 虚拟机装 Ubuntu：只有 Windows 专业版、企业版能用。

  主站也能通过 WSL2 装在 Windows 上。不做 Windows 桌面客户端。依据见 `docs/research/sysbox-2026-11-08.md`。
- 出站访问记录：每次出站记下域名和放行还是拦下，默认保存 30 天，设置里可以改，会话里可以查看。
- 预览：配了单独的预览域名就用它；没配就用主站域名下的路径，并加 CSP `sandbox`（不带 `allow-same-origin`），防止预览页面借管理员的登录调用主站接口。代价是预览页面用不了自己的 Cookie 和 localStorage，所以设置里提示配单独的域名。

### GitHub

- 提交作者默认是管理员本人的 GitHub 账号，用部署向导生成的签名密钥签名（公钥加到本人账号上，提交显示 Verified）；设置里可以改成专门的机器人账号。GitHub App 的机器人身份只有经接口创建的提交才自动签名，用户选了本人账号。
- AI 标识分两个开关：提交尾注；issue、PR 和评论的署名。默认都开。仓库里"按《人工智能生成合成内容标识办法》必须加、用户要求去掉也照加"的说法，改成"默认加上，是否关闭由部署者自行负责"。

### 定时任务

- 不限数量，周期任务最短间隔 1 小时。时区默认取浏览器的时区，设置里可以改。

### 部署、更新、通知和安卓 App

- 网页图形化部署：Linux 上一条命令，Windows 上一条 PowerShell 命令（不做安装包），其余在部署向导里完成：设管理员密码 → 域名和 HTTPS → 一键创建 GitHub App → 填 DeepSeek API key → 添加沙箱宿主机（本机，或在网页上生成命令到别的机器上运行）→ 通知渠道。之后都能在设置里改。用户在功能做全之前不会部署。
- 多渠道通知：SMTP 邮件、PWA 推送、飞书/钉钉/企业微信机器人、通用 Webhook。管理员自己设哪些事件要通知，比如登录、导出完成。
- 检查更新和一键更新在设置里，服务器从本仓库拉取。
- 安卓 App：第一次打开时输入服务器地址或域名。可以借用 DSH Go（社区做的 dsh 安卓 App，AGPL-3.0）的代码，要保留它的版权声明。
