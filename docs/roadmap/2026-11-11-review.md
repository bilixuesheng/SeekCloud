# 路线图和界面的复查（2026-11-11）

用户要求：看看这个项目有没有没考虑到的，前端界面还能不能优化。本文记两件事：界面上查出来并已经改掉的问题，以及路线图（`2026-11-08-handoff.md`、规格 #13）里没覆盖到的地方。

标"待定"的要用户拍板，每条都先写 Claude Code 网页版怎么做，再给建议。标"已补进"的不需要决定，已经写进规格或工单。

## 一、界面

做法：用真主站接假 GitHub、假宿主机跑起来，建了几个会话（正常结束、运行中、准备沙箱、回合失败、沙箱失败），在手机（390 和 320 宽）、电脑、浅色和深色下截图逐屏看。

### 已经改掉的

| 问题 | 怎么改的 |
|---|---|
| 一组工具调用里只要有一次失败，组里每一行的状态点都变红；组在进行中时每一行都转圈 | 状态点的样式只管自己这一行 |
| ✓✓（DeepSeek 已读取）在排队、准备沙箱时就显示了，这时 Agent 还没拿到消息 | 回合开始后才显示，立即发送的插话当场显示 |
| 表格在手机上被挤成一个字一行（"POST"竖着排） | 表格按内容定宽，放不下就整张横着滑，长句子的格子到一定宽度换行 |
| 任务列表的勾选框套了输入框的样式（高 46 像素），和文字不在一行，前面还多一个圆点 | 勾选框和文字排在一行，去掉圆点 |
| 系统字体是 Inter 时（不少 Linux 桌面是），数字之间的 x 被画成 ×：参考号 `k3x9` 显示成"k3×9"，`0x1F` 也会读错 | 关掉字体的上下文替换 |
| 搜索不到会话时提示"暂无会话，输入任务即可开始。" | 改成"未找到匹配的会话。" |

| 代码块没有复制按钮 | 右上角加复制；电脑上指到代码块才显示，手机上一直显示 |
| Agent 的回复没法复制 | 回合结束后，最后一条回复下面加一行：复制这个回合的全部回复（Markdown 原文）和结束时间 |
| 输入框里没发出去的字，换个会话、刷新页面、手机把页面回收以后就没了 | 按会话记在浏览器里，发出去就删掉 |
| 手动选了浅色或深色时，浏览器地址栏和手机状态栏的颜色还是跟着系统 | 跟着选的外观 |

## 二、路线图里没覆盖到的

### 安全

**1. 没有花费的刹车（待定）**

开源版去掉了全部计费和额度，用的是管理员自己的 DeepSeek 余额。但自动跑的东西很多：`/goal` 最多自动 256 轮、`/loop`、定时任务、PR 订阅的自动修复、子 Agent。一个会话跑偏了，可以一晚上把余额用完，没有任何东西拦它。

- Claude Code 网页版：按套餐有 5 小时和每周的用量上限，用完就停。
- 建议：设置里加两个可选的上限，默认不开：每个会话每天的 token 数、全站每天的 token 数。到了就暂停回合并通知，管理员点"继续"接着跑。另外余额低于设定值时通知（余额接口在多提供方那份规格里本来就要接）。

**2. 公开仓库上，陌生人的评论能唤醒 Agent（待定）**

PR 订阅定的是"任何人的评论都能唤醒"。在公开仓库上，任何 GitHub 用户在 PR 下留一条评论，就能让 Agent 开一个回合：花管理员的钱，还把陌生人写的内容送进一个有推送权限的 Agent。评论会标成外部内容，但提示词注入不能只靠标记防。

- Claude Code 网页版：任何人的评论都投递，标为不可信内容。
- 建议：加一个设置"哪些人的评论能唤醒"，可选"所有人"和"仅仓库协作者"（按 GitHub 给的 `author_association` 判断），默认"仅仓库协作者"。CI 失败、合并、关闭这类事件不受影响。

**3. 登录只有一个密码（待定）**

主站放在公网上，登录进去就能指挥一台带着 GitHub 令牌和模型 key 的机器。现在只有密码，加同一个 IP 一小时错 10 次暂停。

- Claude Code 网页版：用 Anthropic 账户登录，支持两步验证。
- 建议：加可选的两步验证（TOTP，验证器 App 扫码）和通行密钥（Passkey）。忘记时照旧在服务器上运行重置命令。可以放在多渠道通知之后做。

**4. 没有反向代理时，频率限制能被绕过（已补进部署向导的规格要点）**

频率限制只认 `X-Forwarded-For` 的最后一个值，前提是"前面正好有一层反向代理"。直接把主站的端口暴露出去时，这个头是客户端自己写的，想写什么写什么。部署向导要问清楚前面有几层代理，没有代理时用连接的来源地址。

### 部署

**5. 中国大陆的网络（待定）**

用 DeepSeek 的人大多在中国大陆，路线图里没提这边的网络：Docker Hub 拉不动，GitHub 时通时不通，npm、PyPI、apt 的默认源很慢。影响三处：安装（拉镜像、装依赖）、一键更新（从 GitHub 拉代码）、沙箱里 Agent 装依赖。

- Claude Code 网页版：没有这个问题。
- 建议：部署向导加一步"网络"：检测 GitHub、Docker Hub、npm 能不能连上，可以填镜像源（Docker 镜像加速、npm、PyPI、apt）和出站代理；通用镜像同时发布到一个大陆拉得动的镜像仓库；沙箱的默认清单把常用的大陆镜像源加进去。

**6. 没有公网地址的部署（待定）**

支持 Windows（WSL2）意味着会有人装在自己的电脑或内网机器上。这时 GitHub 的回调到不了主站：PR 订阅、会话分支被删、仓库权限被收回这些都靠回调。另外 PWA 推送、添加到主屏幕、剪贴板都要 HTTPS。

- Claude Code 网页版：没有这个问题。
- 建议：没配公网地址时，主站改成定时向 GitHub 查询订阅了的 PR（每 1–2 分钟），功能照常，只是慢一点；部署向导里说明内网部署哪些功能受限，并给出用隧道（比如 Cloudflare Tunnel）的办法。

**7. 换服务器、恢复数据（已补进部署向导的规格要点）**

有"导出数据"，没有"导入"。备份并进了部署向导，但要写明：备份必须包括 `SEEKCLOUD_SECRET_KEY`（没有它，库里加密的令牌和 key 全部作废），以及怎么在新机器上恢复。

**8. 主站和宿主机的版本不一致（已补进 #18）**

一键更新会先后更新主站和宿主机，中间有一段时间版本不一样；宿主机在另一台机器上时还可能更新失败。协议已有版本号（`PROTOCOL_VERSION`），连接时要核对：不一致时宿主机不接新会话，并在运行状况里写明要更新哪一边。

### 沙箱

**9. 每个沙箱 30 GB 的磁盘配额靠什么实现（已补进 #18）**

Docker 给单个容器限磁盘（`--storage-opt size=`）只在特定的存储上有效：overlay2 要底下是开了项目配额（pquota）的 XFS，或者用 btrfs、zfs。Ubuntu 默认的 ext4 上不生效，沙箱能把宿主机的磁盘写满。Sysbox 的调研里没查这一点。宿主机那张工单要先在测试机上验证，并定下对宿主机文件系统的要求；向导装宿主机时检查，不满足就明说"磁盘配额不生效"，退回到只靠"磁盘超过 80% 先回收"。

**10. 往沙箱里传文件（待定）**

规格里管理员只能发文字和图片。想给 Agent 一份设计稿 PDF、一个日志、一个压缩包，没有办法。

- Claude Code 网页版：消息里可以附图片和文件。
- dsh 原版：SDK 的组合里有 `file-upload` 和文件引用（dsh 调研第 0 节）。
- 建议：消息可以附任意文件（每个不超过 20 MB，和发给管理员的文件同一个上限），传到沙箱里一个固定的目录，消息里带上路径。放在"模型和思考强度、图片、输入框命令"那张工单之后，单开一张。

### 运维

**11. 按参考号查原始报错（已补进规格 #13）**

ADR 0007 定了给管理员看的错误只有类别、状态码和参考号，原始报错记日志。但规格里没有看日志的地方：管理员拿到"参考号 k3x9"以后，只能登录服务器翻日志文件。设置里加一个"诊断"分类：输入参考号，显示那一条原始报错（只在这里显示）。

### 其他

**12. 界面语言（待定）**

界面只有中文，文案直接写在组件里。

- Claude Code 网页版：多语言。
- 建议：现在不做。开源以后如果有英文用户来问再做；新写的界面不用为此改写法。

**13. GitHub 以外的代码托管（待定）**

只支持 GitHub。大陆不少人用 Gitee、自建的 GitLab 或 Gitea。

- Claude Code 网页版：只支持 GitHub。
- 建议：不做，写进 README 的"不支持"。Git 代理和 GitHub 工具都是照 GitHub 的接口写的，要支持别家是另一份规格的量。

**14. 密钥轮换（待定）**

`SEEKCLOUD_SECRET_KEY`、宿主机密钥、提交签名密钥都没有"换一把"的办法。

- 建议：宿主机密钥可以吊销重发（#18 已有）；签名密钥在设置里可以重新生成（放进提交身份那张工单）；`SEEKCLOUD_SECRET_KEY` 加一个命令行工具，用新密钥把库里的密文重新加密一遍。优先级低。

## 三、安全排查

范围：main 上已有的代码，即主站（登录、接口、GitHub 回调、导出、Markdown 渲染）和宿主机（Git 代理、签名服务、GitHub 工具服务）。模型网关、沙箱、平台工具还没写，对它们的要求记在第 3 小节，会写进各自的工单。

把两种人当对手来看：公网上没登录的人，和沙箱里被外部内容带偏了的 Agent（提示词注入）。后一种更要紧：Agent 手里有推送权限，读的又是别人写的 issue、评论、网页。

### 1. 查出来并已经改掉的

| 问题 | 后果 | 怎么改的 |
|---|---|---|
| Git 代理放行写提交状态和检查结果（`statuses`、`check-runs`） | Agent 可以给自己的提交伪造一个"通过"的必需检查，绕过分支保护，把没人看过的代码合进主分支 | 只留"请求重跑"，其余不放行 |
| 搜索工具把 Agent 的条件和代理补上的 `repo:` 直接拼在一起，而 GitHub 的搜索支持 `OR` 和括号 | 写"密码 OR"就能搜到令牌够得着的别的私有仓库的 issue 和 PR，绕过"只能碰本会话的仓库" | 条件里不接受 `OR` 和括号 |
| Agent 回复里的图片不管来源，浏览器直接加载 | Agent 被诱导时把密钥拼进图片地址，管理员一打开会话，浏览器就把它送到别人的服务器上；沙箱的网络策略管不到浏览器 | GitHub 和主站自己的图片直接显示，别的来源点了才加载（这也是收费版 2026-11-07 定过、还没做的） |
| 主站的接口没有请求体上限 | 登录、webhook 不用登录就能调，发一个几 GB 的请求就能把主站的内存占满 | 接口 1 MB，webhook 25 MB |
| 输错密码的限制按单个 IP 地址算 | IPv6 用户手里通常有一整个 /64，换着地址试等于不受限 | IPv6 按 /64 算一个来源 |
| 经 REST 建引用时只拦标签，别的引用（`refs/notes/` 等）都放行，和推送的规则不一致 | Agent 能建出代理不让它删的引用 | 只放行 `refs/heads/` |
| 要看请求体才能定的请求（推送、建引用）没管 `Content-Encoding` | 代理按原样的字节检查，GitHub 解压以后再读，理论上能让两边看到不同的内容。gzip 的开头不是合法的推送命令，现在骗不过去，但别的编码没有这个保证 | 这两种请求带了 `Content-Encoding` 就拒绝 |
| 主站的响应没有任何安全相关的头 | 少一道保险：万一 Markdown 渲染漏了一处，页面里就能跑别人的脚本 | 加内容安全策略（脚本只能来自本站，不允许内联脚本）、不允许被嵌进框架、`nosniff`；启动时设外观的内联脚本挪到单独的文件 |

### 2. 看过、没有问题的

- **登录**：密码只存 scrypt 哈希，比对不受计时影响；登录状态的令牌是 32 字节随机数，库里只存哈希；Cookie 是 HttpOnly、SameSite=Lax；改密码后其他设备退出。
- **跨站请求**：接口只收 JSON，表单类型的跨站请求被中间件拒绝，Cookie 的 SameSite 是第二道。
- **每个接口都先查登录**，会话、导出都按管理员的 ID 过滤。
- **关联 GitHub**：state 存在 HttpOnly 的 Cookie 里核对；授权后跳回的地址只认固定的两个。
- **webhook**：先验 HMAC 签名（比对不受计时影响）再解析。
- **令牌存放**：GitHub 令牌用 AES-256-GCM 加密存库，密钥在环境变量里。
- **导出**：压缩包里的文件名用会话短 ID，不用标题；下载前按 ID 和管理员查库。
- **Markdown**：按白名单渲染，原始 HTML 当文字显示，链接只认 `http(s)` 和 `mailto`。
- **Git 代理**：
  - 目标主机取自 CONNECT 的地址，请求里的 Host 头不参与，骗不了它把令牌发到别处；
  - 路径里的 `//`、`..`、编码过的斜杠一律拒绝，检查的和转发的是同一个规范化后的路径；
  - 推送命令的解析遇到看不懂的格式（包括签名推送）就拒绝；
  - 会话结束后，已经建好的连接上的请求也不放行。
- **GitHub 工具**：路径里的参数逐段编码并再过一遍代理的规则；GraphQL 只有写死的几条，调用前都确认了仓库挂载在本会话。
- **签名服务**：只签 git 的提交和标签对象，只签提交者是指定邮箱的。

### 3. 设计上的风险，需要用户知道或拍板

**3.1 提交用管理员本人的身份签名（已定，说明风险）**

提交作者定了默认用管理员本人的账号，签名密钥在宿主机上、公钥加在本人账号上。签名服务没法知道一个提交是给哪个仓库的，所以拿到会话令牌的 Agent 可以让它签任意内容的提交。这个签名是可以带走的：把签好的提交对象传出去，推到任何仓库都显示"管理员本人 · Verified"。用专门的机器人账号时，冒充的只是机器人。

- Claude Code 网页版：提交者是 Claude 自己的账号，不是用户本人。
- 建议：保持已定的默认，但部署向导和设置里把这一点写明，并把"机器人账号"作为更稳妥的选项并列出来。另外签名服务加一条：提交者时间和当前时间差太多的不签，免得被拿去伪造"很久以前的"提交。后一条可以直接做，要不要做请定。

**3.2 Agent 能以管理员的身份批准和合并 PR（照 Claude，说明风险）**

Git 代理放行合并 PR 和提交 review，Agent 用的又是管理员本人的令牌。别人从 fork 提一个 PR、在评论里写一段诱导的话，Agent 就有可能批准并合并它。计划里的防线是自动模式下的安全审查（"合并没人批准的 PR"默认拦下），和上文第二节第 2 条（只让协作者的评论唤醒）。这两条做好之前不要在公开仓库上开 PR 订阅。

**3.3 暴力破解只有按来源限速这一道（待定，同第二节第 3 条）**

没有全站的上限，也没有两步验证。攻击者有很多个 IP 时，每个 IP 每小时 10 次，加起来没有上限。加全站上限的代价是：别人可以故意输错，让管理员自己也登不进去。建议做两步验证，不做全站上限。

**3.4 首次设置密码没有保护（已定）**

装好以后、设置密码之前，谁先打开网页谁就是管理员。用户已经定了不做防抢先。部署向导做的时候把"装好马上设置"写在命令的输出里。

**3.5 `/api/health` 不用登录就返回版本号**

方便监控，也方便别人知道跑的是哪个版本。建议没登录时只返回状态，版本号登录后才给。改动很小，要不要改请定。

### 4. 还没写的部分，安全上的要求（写进各自的工单）

- **预览和发给管理员的 HTML 文件**：没配预览域名时走主站域名下的路径，浏览器会把登录 Cookie 一起发过来。代理转发给沙箱之前必须去掉 `Cookie` 和 `Authorization` 头，沙箱返回的 `Set-Cookie` 也去掉。不然沙箱里的程序能拿到管理员的登录状态。
- **出站网络**：任何一档（包括"完全开放"）都不能连宿主机自己、内网地址（10/8、172.16/12、192.168/16、169.254/16、回环、IPv6 的对应网段）和云厂商的元数据地址，除非管理员在设置里明确放行。装在家里或办公室内网的机器上时，不然沙箱能扫整个内网。出站代理按解析后的 IP 判断，防止域名解析到内网地址。
- **宿主机执行命令**：仓库名、分支名、文件路径进 git 和 docker 的命令行时，一律用参数数组，不拼字符串；以 `-` 开头的分支名前面加 `--`。
- **模型网关**：沙箱发来的 `x-api-key`、`Authorization` 一律丢掉，只用主站自己存的 key；会话临时令牌和宿主机凭据的比对不受计时影响。
- **平台工具**：每次调用都按会话临时令牌确定是哪个会话，参数里的会话 ID 只能是同一个管理员的；`create_session` 的权限模式不能比调用方宽。
- **自接 MCP**：OAuth 发现和回调里出现的地址来自远程服务，主站去取之前同样不连内网地址。
- **宿主机密钥、会话临时令牌、Webhook 回调地址里的令牌**：都是 32 字节随机数，库里只存哈希，不进日志。
