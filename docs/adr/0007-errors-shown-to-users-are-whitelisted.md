# 给用户看的错误只有类别、状态码和参考号

2026-11-01 用户要求：API 出错时只报关键信息，不能把完整的报错给用户，否则可能泄露后台设置的 API 端点。

上游的原始报错经常带着这些东西：接口地址、上游的模型名、请求编号、限流额度，有时还有密钥的前几位和后几位。所以从上游到用户的每一段，都只传结构化的三样：

- **类别**（`ErrorCode`，协议包里的固定列表）：模型服务不可用、限流、拒绝、超出上下文、超时、额度用完、建不了沙箱、克隆失败、内部错误；
- **状态码**：上游返回的 HTTP 状态码，400 到 599 之间的才留；
- **参考号**：我们自己随机生成的编号，不用上游的请求编号。原始报错只记在日志里，用参考号查。

界面上的说明文字由浏览器按类别生成，比如"回合失败：模型服务暂时不可用（502 · 参考号 k3x9）"。

具体每一段怎么做：

- **模型网关 → 沙箱**（工单 10 #25、工单 49 #64）：
  - 上游出错时，网关给沙箱回一个 Anthropic 格式的错误，`message` 是我们自己写的说明加状态码和参考号，不转发上游的响应体。
  - 不管成功还是失败，上游的响应头都按白名单转发：只留 `content-type` 和 `retry-after`。上游的请求编号、限流额度、服务器名这类头一律去掉。
  - 响应里的 `model` 换回我们的模型 ID，消息的 `id` 换成我们自己生成的。不同平台的编号格式不一样，从编号能看出走的是哪家。
  - 所有线路都失败时，Agent 看到的也只是这一个错误。用户看不到线路的名字，也看不到试过几条线路。
- **宿主机 → 主站**：协议里的 `sandbox.failed` 和 `turn.ended` 只带 `SafeError`，没有自由文本的字段。主站收到以后再用 `toSafeError` 按白名单过一遍：宿主机的代码就算出了错、多带了字段，也到不了浏览器。
- **Git 代理和出站代理**：连不上上游时，沙箱里只看到错误码（比如 `ECONNREFUSED`），原始报错只记日志。
- **主站接口**：
  - 出了没预料到的错误，统一返回"服务器出错了"，详情只记日志（`handleError`）。
  - 给用户的接口（比如 `/api/models`）不带任何线路信息。
- **管理端**：管理员能看到每条线路最近的原始报错，只有管理员能看。

## Considered Options

- **在报错文本里用正则把网址、IP、密钥打码，再给用户看**：没有采用。黑名单总有漏的，比如编码过的地址、只带域名一部分的报错、换了格式的密钥。只传白名单里的结构化字段，从根上就没有自由文本。
- **什么都不给，只说"出错了"**：没有采用。用户分不清是该重试、该缩短对话还是该等额度恢复，报问题时我们也查不到是哪一次。

## Consequences

- 用户报问题时要给出参考号。宿主机和主站的日志要按参考号能查到原始报错，日志保留时间跟用量记录一致。
- 以后加新的错误类别，要同时改协议包的 `ERROR_CODES` 和浏览器里的说明文字（`apps/site/src/client/session/errors.ts`）。
- Agent 自己的输出（消息、工具结果）不在这条规则里：那是沙箱里的内容，用户本来就能看到。沙箱里本来也没有上游的地址和密钥（ADR 0003），所以 Agent 输出不了这些。
