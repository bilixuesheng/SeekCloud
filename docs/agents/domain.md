# 领域文档

各个工程技能在读代码之前，按这里的规则使用本仓库的领域文档。

## 先读这些

- 仓库根目录的 **`GLOSSARY.md`**。
- **`docs/adr/`**：读和你要动的部分有关的 ADR。

本仓库是单一上下文：只有一份 `GLOSSARY.md` 和一个 `docs/adr/`。

这些文件如果缺了，**不用提**，也不要主动建议创建。`/domain-modeling` 会在术语或决定真正定下来的时候再写。

## 用术语表里的叫法

输出里提到领域概念时（issue 标题、重构建议、假设、测试名），用 `GLOSSARY.md` 里定义的词，不要换成它明确列为"避免"的同义词。

需要的概念不在术语表里，说明两种情况之一：要么你在发明项目里不用的说法（重新考虑），要么术语表真有缺口（记下来，交给 `/domain-modeling`）。

## 和 ADR 冲突时要明说

如果你的输出和某个 ADR 相矛盾，要明确指出，不要悄悄推翻：

> _和 ADR 0003（凭据一律不进沙箱）相矛盾，但值得重新讨论，因为……_
